# AUDIT — tous les concepts & le site (17 Sep 2026)

Déclencheur : King a trouvé, dans l'aperçu opticien, un paragraphe **blanc sur blanc**. Cause réelle : en insérant le miroir dans la section « formes », j'avais **supprimé un `</div></section>`** ; tout ce qui suivait est devenu **enfant de la section sombre** `section.shapes` et a hérité de son `color:#fff` — les cartes blanches affichaient donc du blanc. Le fichier restait **équilibré** (les balises se refermaient plus loin), donc un simple contrôle d'équilibre ne l'aurait pas vu : il fallait vérifier la **hiérarchie**.

## 1 · Ce qui a été construit pour que ça ne repasse pas
`tools/qa/audit_a11y.py` (24/09) — audit d'**accessibilité WCAG 2.2 AA, critère par critère** : chaque constat porte son numéro (`[1.1.1]`, `[2.4.7]`, `[3.3.2]`…), parce qu'un rapport d'accessibilité se lit ainsi. Il refuse une page ET il dit ce qu'il a trouvé conforme. Testé par `tools/qa/test_audit_a11y.py` : douze défauts attendus sur une page fautive, zéro alerte sur une page saine — un contrôle d'accessibilité qui n'a jamais été pris en défaut est un contrôle qu'on n'a pas testé.

`tools/qa/audit_html.py` — audit pré-livraison, sans navigateur :
- **STRUCTURE** : équilibre des balises **et** sections imbriquées dans une section (la classe exacte du bug ci-dessus).
- **CONTRASTE** : ratio WCAG de **chaque texte** du fichier, calculé depuis le CSS du fichier (cascade spécificité + ordre + styles inline + `var()` + `clamp()`), fond réel hérité et composité (alpha), seuils 4.5:1 / 3:1 (grand texte).
- Deux contextes évalués : **desktop** (base + min-width) et **mobile** (base + max-width) ; une trouvaille n'est « confirmée » que si elle existe dans les deux.
- Sortie code 1 s'il reste quoi que ce soit → utilisable comme **porte de livraison**.

Deux faux positifs corrigés dans l'outil même (leçon : un auditeur doit être vérifié avant de juger) :
`::after/::before` étaient appliqués aux éléments (ils inventaient des fonds) ; les emojis (glyphes colorés) étaient traités comme du texte.

## 3 · Nature des correctifs appliqués
- **Afrique Labo** : le jeton `--cyan-d` (libellés en petites capitales sur fond clair) passe de `#0C8FAB` (3.62:1) à **`#0A7388`** (5.24:1).
- **OraCare / YAKS / Skye** (mêmes paquets CSS) : bloc a11y appliqué en fin de feuille — or sur fond clair → `#3F7A1E` ; or sur navy → `#B6E88F` ; pastille de numéro navy + texte crème ; pilules d'adresse en vert foncé ; `.btn-dark` en dégradé sombre ; `--slate` des cartes → `#475C70` ; textes secondaires sur navy à 92 % au lieu de 60-75 %.
- **Opticien** : jeton de texte `--clay-text:#A8542C` (5.29:1), `--mute` → `#557076` (4.93:1), et surtout **les composants possèdent désormais leur couleur** : `.card,.quote,.faq{color:var(--ink)}` — plus jamais l'héritage d'un fond sombre.

## 4 · Règle (ajoutée au pré-vol)
**Toute livraison passe `python3 tools/qa/audit_html.py <fichier>` et doit sortir à 0 trouvaille confirmée.** Le contrôle tourne sur le fichier construit, pas sur le builder.
