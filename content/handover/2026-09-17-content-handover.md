## 7. Don'ts and mistakes to avoid

### Creative/strategic mistakes
- **Don't return to generic rectangle-only website diagrams.** User explicitly requested realistic webpages.
- Don't make the entire video a talking head or an avatar reading a script.
- Don't hide an important flow diagram over detailed background art. #1 received this criticism.
- Don't cover a WhatsApp button with a caption while explaining that button.
- Don't force all list questions onto the same screen when the narration presents them individually.
- Don't promise virality, “maximum reach,” leads or ranking gains.
- Don't treat tiny view samples as statistically convincing or ignore differing post ages/platforms.
- Don't introduce unrelated content directions just because one post improved.
- Don't retrofit the PREVIEW CTA into all earlier videos without confirming the requested scope. Only latest #4 currently has it.
- Don't imply uploads, profile edits, tracking setup, DM handling or posting were performed when they were only recommended.

### Earlier advice that needs qualification

Some earlier responses gave overly confident generic Instagram advice: fixed best posting windows, minimum weekly posting frequency so an algorithm “learns,” exact engagement-weight hierarchies, and a prescribed hashtag count. Treat these as unverified suggestions, not standing facts. Use current platform guidance/account insights when relevant, distinguish cover-grid behaviour from autoplay hooks, and avoid unsupported algorithm claims.

One earlier response called 40.38 seconds “inside” a 35–40-second brief. It is not. Report exact duration; seek permission or tighten pacing when a hard maximum applies.

An earlier assistant said it could not see frames, although image-inspection tools were available. **Inspect frames when possible; never claim inability or verification inaccurately.**

### Technical failures already encountered

- Heavy FFmpeg graphs combining seven full-resolution video inputs exhausted the small sandbox's memory. Prefer browser capture + PIL frame composition or small sequential compositing passes.
- An early script used the wrong loop variable in output filenames, leaving only the last clip. This was wrongly blamed on cleanup. Inspect code before inventing environmental explanations.
- Input and output were once both `tmpcap.mp4`; FFmpeg cannot edit files in place. Use unique paths per step and distinct final revision names.
- Mixed/default frame rates appeared in earlier work. Explicitly set input/output rates, `fps=30`, output `-r 30`, and square pixels (`setsar=1`). Verify final output rather than merely asserting compliance.
- Multiline Bash filter syntax accidentally produced an array instead of one filter string. Use a Python argument list or a single correctly quoted filter string.
- Font files named “ExtraBold” were variable fonts that rendered thin until the weight axis was set. Current PIL helper uses `set_variation_by_axes([800])` for bold and `[500]` for regular, with a fallback.
- Some font glyphs (check marks/arrows) rendered as missing boxes. Draw simple marks with vector/PIL lines if the font lacks the glyph.
- FFmpeg package paths changed after environment resets. Resolve with `imageio_ffmpeg.get_ffmpeg_exe()`; do not trust an old hard-coded Python-version path.
- Playwright Chromium initially lacked system libraries. `python -m playwright install-deps chromium` resolved that in this environment.
